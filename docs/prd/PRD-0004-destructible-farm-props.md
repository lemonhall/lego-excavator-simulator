# PRD-0004: 可拆卸农场物件

## Vision

玩家驾驶乐高风格挖掘机时，农场里的树木、篱笆和小屋不应只是静态摆设。履带/车身撞击和大臂/铲斗触碰都必须让这些物件进入可见的拆卸状态，散开的碎块仍保持乐高塑料积木质感。v5 已交付稳定、可测试的“玩具式拆卸”；v6 根据 ECN-0006 升级为 Rapier 真实刚体碎块，让拆毁反馈包含重力、碰撞、冲量和落地过程。

## Requirements

### REQ-0004-001: 可拆卸目标登记

- **动机**：状态层需要知道哪些场景物件可以被挖掘机拆卸，否则无法做可回归测试。
- **范围**：登记树木、篱笆、小屋三类目标；每个目标必须有稳定 `id`、`kind`、世界坐标、触发半径、耐久值和状态。
- **非目标**：不登记庄稼、路径砖、零散圆点积木。
- **验收口径**：`createInitialGameState()` 返回的 `destructibles` 至少包含 `barn`、`tree0`、`fence0`，并包含三类 `kind`。

### REQ-0004-002: 履带/车身撞击拆卸

- **动机**：玩家开挖掘机直接撞上树、篱笆、小屋时必须看到破坏反馈。
- **范围**：驾驶模式下，挖掘机底盘中心进入目标触发半径后减少耐久；篱笆和树木可一次进入 `detached`，小屋需要多次命中。
- **非目标**：步行玩家不会拆卸场景物件。
- **验收口径**：单元测试能证明驾驶挖掘机撞到篱笆后其状态不是 `intact`，撞到小屋多次后进入 `detached`。

### REQ-0004-003: 大臂/铲斗触碰拆卸

- **动机**：挖掘机的工作装置必须有真实用途，而不是只有车身能撞东西。
- **范围**：根据挖掘机位置、上车回转角、大小臂和铲斗角度估算铲斗触点；铲斗触点进入目标触发半径后减少耐久。
- **非目标**：不做精确多段机械臂网格碰撞。
- **验收口径**：单元测试能证明挖掘机车身未贴近树木时，铲斗触点进入树木半径也能拆卸树木。

### REQ-0004-004: 乐高化拆卸视觉

- **动机**：拆卸反馈必须像积木散开，而不是物件消失。
- **范围**：世界层把可拆卸目标组成稳定 group；`damaged` 和 `detached` 状态改变 group 内碎块的位置、旋转、可见性或倾倒角度；debug 暴露计数。[已由 ECN-0006 扩展为 Rapier 动态碎块]
- **非目标**：不引入粒子烟尘；v6 不把整台挖掘机改成动态车辆刚体。
- **验收口径**：E2E 驾驶挖掘机撞击目标后，`window.__legoGameDebug.destructibles.detachedCount` 大于 0，且场景中仍存在带 `destructibleShard` 标记的乐高碎块。

### REQ-0004-005: Rapier 物理碎块

- **动机**：v5 预摆碎块缺少重力、碰撞和冲量，实际观感不可信。
- **范围**：使用 Rapier 管理可破坏物理装配体；树、篱笆、小屋从初始状态就是多个带 collider 的乐高零件；零件之间有 breakable links；地面为 fixed collider；挖掘机车身/履带/铲斗为 kinematic collider；连接断开后零件以 dynamic rigid body 散落；每帧同步 rigid body transform 到 Three.js mesh。
- **非目标**：不实现真实履带车辆动力学，不模拟复杂材料断裂，不要求所有未碰撞零件一开始就自由散落。
- **验收口径**：E2E 驾驶挖掘机撞击目标后，debug 显示 `engine: "rapier"`、`assemblyBodyCount > 0`、`activeLinkCount` 下降、`brokenLinkCount > 0`、`kinematicColliderCount >= 2`，并且至少一个零件的高度或世界位置在连续采样中发生变化。
